## §3 需要源项目确认 / 处理

### 3.1 `lastWords`（遗言）与 `deepMode`（4 人深度模式）：类型里有，逻辑里没人读

**证据**（QQBot 侧 2026-09-16 全仓检索 `.ts` + `.tsx`）：

- 声明处：`shared/types/game.ts:205-206`
  ```ts
  lastWords: boolean;
  deepMode: boolean;
  ```
- 唯一赋值处：`client/src/components/CreateRoomModal.tsx:73-74` —— 硬编码 `false`，UI 上**没有开关**
- 服务端逻辑里**没有任何读取处**（0 命中）
- 测试里只有构造 settings 时顺手写上：`server/game/__tests__/bugfixRegression.test.ts:62-63`

**需要决定**：实现它，还是把字段删掉（连同客户端硬编码）？
顺带一提：QQBot 侧**没有**实现这两项（按"不属迁移目标"处理），所以源项目怎么定都不会影响移植。

### 3.2 `houndWhistle`（猎犬哨）：常量与 UI 标签都有，但永远不会发到玩家手里

**证据**：

- 常量：`shared/constants.ts:98`（`ITEMS.HOUND_WHISTLE = 'houndWhistle'`）
- 客户端会显示它：`client/src/game/PhaseHeader.tsx:24`、`client/src/game/ReplayLog.tsx:34,63`（`场上存活 N 只狼`）
- 但**物品池里没有它** → 玩家永远拿不到 → 这条展示分支是死代码

**需要决定**：把猎犬哨放进物品池（例如 7 人及以上局），还是删掉？
（QQBot 侧已按"补齐"处理：7 人及以上局默认进池，见移植计划的 §2.3。）

### 3.3 警长系统：代码里完全没有

`.ts` / `.tsx` 全仓 **0 命中**（连常量都没有）。可能只存在于设计文档。若确实是废弃设计，建议在设计文档里标注"未实现/已废弃"，免得后来者以为漏做了。

### 3.4 （低优先级）`items.pool` 空数组的语义

源项目取物品池时若写成 `settings.items.pool || DEFAULT_POOL`，JS 语义下 **空数组是 truthy** → 显式传"空池"会被忽略、改用默认池。
需要确认：UI 上是否存在"启用物品但一个都不选"的可达路径？若可达，则这是一个静默改变用户设置的小 bug。
（QQBot 侧 Python 的 `or` 对 `[]` 是 falsy，会得出**相反**结论，所以这一项被单独记下来对齐语义。若判定不可达，忽略即可。）

### 3.5 已排查、**确认不是 bug** 的一处（留档免得重复查）

`submitDisconnectedFallback` 的超时回调只校验 `actionId` / `connected` / `submitted`，**没有校验玩家是否已出局**。
我推导了三条可能路径：① 阶段切换（`activeAction` 变了）② 本次行动作废 ③ 认输——三条都被 `current.actionId !== actionId` 这一行挡住，因此**不可达**，不构成 bug。
