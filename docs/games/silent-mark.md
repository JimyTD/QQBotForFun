# 🌙 静夜标记（Silent Mark）

> 源项目：`d:/Fun/SilentWereWolf`（TypeScript 全栈 Web 版，v0.2.1）
> 本仓库位置：`src/plugins/games/silent_mark/` · 注册 id `silent_mark`
> CLI：`uv run python scripts/play_cli.py silent_mark [板子]`

## 一句话

**删掉自由发言的狼人杀**：玩家不聊天，改为按座位顺序公开放「标记」
（1 个身份声明 + 若干条对他人的评价），再投票放逐。

它天生适合群聊：**零语言门槛**——不要求打字快、不要求会辩论，
所有信息都是结构化的标记与投票记录。代价是夜里要私聊，所以
**所有玩家都必须先加机器人为好友**（这是硬前置，不是建议）。

## 玩法

1. **夜晚（私聊）**：守卫 / 狼人 / 女巫 / 预言家 / 守墓人各自收到一条私聊问询；
   没有夜间能力的角色**不会被打扰**。狼人逐个私聊，后表态的狼能看到队友当前意向。
2. **死讯（群内）**：只说谁出局，**绝不说死因**——平安夜 / 被守住 / 被解药救 / 狼人空刀
   在公告上完全等价（这是这个游戏的核心信息设计）。
3. **死亡触发（私聊）**：猎人开枪、白狼王带人、骑士决斗。
   **真的带走了人才公开**（那是设计预期的翻牌）；**选择跳过只私聊告知本人**——
   公开"他没开枪"等于白送狼人一个身份。
4. **标记发言（群内，按座位顺序）**：
   `@我 标记 好人 直觉判断 | 3号 狼人 标记分析 | 6号 好人`
   （理由可省略；不会写就只发 `@我 标记`，机器人在私聊里一步步带你）
5. **投票放逐（私聊征求）**：收齐后一次性公布明细与结果。
6. **结算**：公布胜负、原因与全部身份；胜负双方都给正向奖励。

## 板子（12 套预设 + 自定义）

`4standard` / `5standard` / `6standard` / `6gods` / `7standard` / `8wolfking` /
`8knight` / …（权威清单见 `engine/constants.py:PRESETS`，CLI 与 QQ 菜单共用这一份）

人数规则：**恰好等于板子人数**（源项目同口径，不多也不少）。
房主可以在报名阶段 `@我 板子 6gods` 换板子。

### 自定义板子

`@我 板子 自定义`（或开局时直接 `@我 静夜标记 自定义`）→ 房主在**私聊**里走一遍分步向导：

1. 人数（4~12）
2. **逐位落座**：每个座位选一个角色（源项目 UI 就是"每位一个下拉"，
   逐位选能保证人数绝对精确，不会配到一半发现人数不对）
3. 胜负条件（屠边 / 屠城）
4. 随身物品开 / 关
5. 总览 → 确认 / 重选 / 取消

不合法（好人不多于狼、屠边缺神职或平民、人数越界…）会**说清原因并让你重选**，
绝不开出一局坏棋。向导全程在私聊，群里只在最后出一次房间面板。

> 实现上这份向导是 `custom_setup.py` 里**一个函数**，群里和 CLI 调的是同一份
> （`docs/13-cli-bot-parity.md` 铁律）：`play_cli.py silent_mark custom` 走的就是它。

## AI 补位（默认开启）

**人数不够就用 AI 填满**：房主不必凑满一桌。房主可用 `@我 AI 关` 关掉（那时人数必须
恰好等于板子人数）、`@我 AI 开` 打开、`@我 AI 测试` 确认 AI 链路是否真的通
（不会"默默走兜底"）。

- **AI 与真人同权**：AI 的决策会被翻成和真人**一样的输入**，走同一个解析器和
  同一条规则层校验 —— 不开后门，这是结构上的保证（`ai/controller.py`）。
- **AI 不能开天眼**：上下文只喂该座位有权知道的信息，私有部分直接复用
  `engine/private_info`（真人看到什么，AI 就看到什么）；夜间死因对 AI 也只显示"被袭击"。
- **不会卡死**：LLM 报错/超时/返回垃圾 → 重试一次 → 仍不行就走角色专属确定性兜底
  （与真人断线代打同一条路）。LLM 完全不可用也能打完整局。
- **超时**：AI 有超时（各阶段 20~120 秒），**真人永远不被计时**。
- **人格**：6 种分析人格（标记细读 / 投票追踪 / 关注低调 / 死亡线索 / 独立思考 / 直觉流）
  开局洗牌分配、整局固定；另有"模拟思考延迟"，让节奏更像真人。
- **决策日志**：每局一份 `logs/silent_mark_ai/<会话>.jsonl`，记录喂了什么、模型回了什么、
  守卫是否纠正、是否落到兜底 —— 排查"AI 表现怪"靠它。

模型场景在 `config/llm.yaml`：`silent_mark_ai`（决策，glm-4-flash-250414，低温要 JSON）
与 `silent_mark_ai_name`（取名，高温短输出）。想换更强的模型只改这里。

## 物品与遗物

开局每人发 1 件（可在房间阶段 `@我 物品 关` 关掉）。**存活时只看得到类型，看不到内容**；
出局时整件公开成遗物（这是本作最有辨识度的信息设计）。

| 物品 | 内容 | 什么时候算出来 |
|---|---|---|
| 月光石 | 被夜间行动造访过几次（一夜最多 +1，去重） | 每夜结算时累加 |
| 天平徽章 | 左右邻座是否同阵营 | 开局座位确定后 |
| 猎犬哨 | **出局那一刻**场上还剩几只狼 | 出局瞬间（`record_death` 里快照，不含自己） |

7 人及以上局默认把猎犬哨放进池子（源项目定义了却从未启用，本侧补齐）。

## 交互设计（为什么群里不乱）

群里只有两类东西：

1. **对局面板**——一条消息，状态变了就原地更新（删旧发新）。板子、座位、阶段、
   轮到谁、本轮标记记录、投票进度全在里面，**所以群消息条数不随回合增长**；
2. **关键时刻的独立公告**——死讯 / 开枪 / 放逐 / 投票结果 / 结算（要能翻回去看）。

另外：当前提问群里同时只留一条（下一个人的提问发出时，旧的撤回）；
玩家自己的指令消息**发完即撤回**；私聊里每个座位只留最新一条提示
（身份牌单独占一条，结算后保留便于复盘）。

实测量级（6 人局跑完一整轮）：群内净留存 5~7 条。
回放脚本 `scripts/demo_silent_mark.py` 会打印每局的"净留存"指标。

## 超时（本仓库大原则）

- **真人没有单步超时**：`session.ask(timeout=None)`，永远等下去。
  有人挂机就把这局僵在那儿，这是可接受的；收场靠 `@我 结束`（人人可用）。
- **只有 AI 补位座位**才有超时（`config.py` 的 `ai_*_timeout`，AI 见 M4）。
- **整局兜底**：全局 `game_session_timeout_hours`（默认 24 小时），
  由 `GameBase.default_session_timeout_seconds` 统一提供。

## 文件结构

```
silent_mark/
├── engine/          纯规则内核（无 IO、无 NoneBot）：常量/角色/结算/兜底/私有信息
├── syntax.py        输入解析 + 输入提示（解析与提示必须配对）
├── views.py         状态的可读表达（看板 / 公告 / 身份牌 / 记录 / 结算）
├── game.py          状态机 + 交互 + 消息生命周期（唯一的 IO 出口是 `_ask`）
├── commands.py      报名房间与指令
└── config.py        可调参数（AI 超时、重试轮数、奖励）
```

## 开发须知

- **加规则先加测试**：`tests/games/silent_mark/` 里 `test_resolve.py` / `test_roles.py` /
  `test_private_info.py` 是从源项目 `p0Rules.test.ts` / `privateInfo.test.ts` 逐条转写的，
  改规则前先看它们。
- **信息防火墙**（`game.py` 的 `_ask(sensitive=...)`）：私有动作出问题只私聊本人，
  **群内一个字都不发**。改任何公告前先问一句"这句话会不会暴露某个座位有夜间身份"。
- **两个"已死但还要行动"的场景**（猎人/白狼王）依赖 `_ask` 的 `was_alive` 判断，
  不要退回"当前已出局就作废输入"的写法。
- **CLI 对齐**：`scripts/cli_adapters/silent_mark.py` 不复刻规则，它把真实游戏跑起来、
  把会话 IO 接到终端。所以改文案不用同步 CLI；但**改交互时机**（谁什么时候被问）
  要跑一遍 CLI 验证。
