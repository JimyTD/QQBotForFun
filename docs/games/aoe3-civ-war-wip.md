# 帝国3斗蛐蛐国战 WIP

> 状态：一期主流程已编码，待配置校准、玩法验收与群测。

## 已确定

- 入口：`斗蛐蛐 国战` 随机两个主文明；`斗蛐蛐 国战 文明A 文明B [预算] [3-5时代]` 指定对阵。
- 只使用 `civs.json` 中 24 个可玩主文明；不纳入革命、战役文明、原住民部落或盟友单位。
- 时代规则沿用普通斗蛐蛐：兵池按时代限制，逐时代单位改良和土著/亡命徒/佣兵类别科技继续生效。第一期国战只开放 3 至 5 时代，默认 3 时代；2 时代荷兰等文明无法凑出完整、可竞争的战术编制，不作为国战对局时代。
- 普通对局和国战都不使用随机通用科技。未来科技只能来自本国、可解释且公开展示的科技树或主城国策。
- 国战重点是“国家战术编制”，不是把文明可用单位简单随机拼在一起。

### 文明时代升级与皇家护卫

国战按文明应用时代升级。普通斗蛐蛐继续使用不带文明上下文的 `unit_upgrades.json`；国战额外读取 `civ_unit_upgrades.json`，避免英国红衫军的加成污染其他文明共享的火枪兵。

文明升级数据由 `techtreey.xml` 自动生成，不维护手写 RG 数值表。生成器从文明 `Age0` 科技得到该文明可研究的升级，沿 `TechStatus active` 与 `prereqs` 构建科技依赖图，并保证每个科技节点只应用一次。它同时覆盖：

- RG 激活普通 Guard、再附加额外增量，例如法国散兵和英国红衫军；
- RG 自身包含完整护卫档，例如奥斯曼乌鲁菲利；
- 不以 `RG` 命名的皇家护卫替代线，例如意大利伽利略臼炮/重弩长炮和马耳他蛇怪炮；
- 丹麦全陆军、波兰多条皇家护卫线，以及亚洲、非洲、原住民自己的 Honored / Exalted / Champion / Legendary 升级。

文明覆盖层支持血量、攻击、名称、射程、射速、速度、护甲、倍率和单位成本变化。例如葡萄牙法令长矛兵的成本降低、波兰镰刀兵的攻速变化都必须生效。3 时代仍与通用老练档一致，文明差异从各自真实科技生效时代开始。

## 国家正规军池

候选单位先通过普通斗蛐蛐的安全过滤，再额外排除英雄、探险家/侦察兵、宠物、纯治疗者和专职爆破/攻城单位（炸药筒、隐匿炸药筒、攻城槌）。村民（包括法国库尔人）、建筑、船、占位符、战役垃圾单位、彩蛋和怪物都不入国战。不能按 `AbstractSiegeTrooper` 整类排除：草原骑兵、弓箭武士、俄国重骑等正规军也带这个标签。

雇佣兵、亡命徒和领事馆远征军都是游戏内合法军力，不全局禁止。领事馆单位只要具有正常资源费用、且不是 `AbstractBannerArmy` 代币，就和其他可训练战斗单位一样参与候选编制。国家辨识度依靠本国兵种和编制结构体现，不靠人为排除合法单位。

但“合法费用”不是唯一标准。间谍、密探等带 `MercType2` + `AbstractCanSeeStealth` 的侦隐特工不属于可批量部署的国家正规军；印度 `*mansabdar` 是一名上等曼萨卜达尔的强化版本，也不能被数量分配器扩成几十名同类单位。两者都要在国战池中显式排除，并在审计输出中列出原因。领事馆远征军不受这条规则影响。

文明白名单必须读取 `civs.json` 的 `_meta.curated_civs`，不能用 `is_main` 推断；后者还会包含战役、剧本等非 24 个可玩主文明条目。

## 战术编制生成

### 运行时：生成而非预演

1. 结合 type 标签、攻击方式、射程、移速、护甲和克制倍率，把单位标记为火枪、散、马、龙骑、近战反骑重步、炮等战术生态位；一个单位可兼任多个生态位。原始 type 只提供初判证据，不能直接决定生态位。
2. 每个文明先生成 2 至 3 兵种的候选编制，不做一次随机抽兵就直接开战。
3. 候选优先从玩家熟悉的常见组合骨架生成，而不是自由拼接：

   | 组合 | 骨架 | 作用 |
   |---|---|---|
   | 火枪马 | 火枪前排 + 高机动近战冲击 | 前排反骑、与轻步交战；机动单位切散、切炮、压后排。后者不限于骑兵。 |
   | 龙骑散 | 机动远程反重骑 + 散 | 远程骑兵/等价单位处理重骑和追击，散处理重步。 |
   | 散马 | 散 + 高机动近战冲击 | 散兵远程打重步，机动近战切散和炮。 |
   | 火枪炮 | 火枪前排 + 反步兵炮 | 火枪掩护炮兵，炮兵处理成团步兵。 |
   | 龙骑炮 | 机动远程反重骑 + 反步兵炮 | 龙骑保护炮兵并处理重骑，炮兵处理成团步兵。 |
   | 火枪散 | 火枪前排 + 散 | 火枪负责前排反骑，散负责远程反重步。 |
   | 重步散 | 近战反骑重步 + 散/弩 | 近战重步保护后排、反骑，远程位反重步；长矛 + 弩手只是经典实现。 |

另有一个固定三兵种扩展：散兵/弓手 + 龙骑兵 + 反步兵炮（“散龙炮”）。它是龙骑散的明确扩展，不是从三个可用单位中任意抽出的组合；只在该文明有这三种角色时生成。社区教学和实战讨论把 `skirm / huss / goon`、`musk / huss`、`musk / art`、`skirm / goon + falconet` 都作为常见的竞技体系，因而没有必要再添加同义的泛化骨架。

### 生态位判定

国战不维护一张覆盖全部单位的手工职业表。运行时以帝国 3 的逻辑克制标签为主判定，攻击属性只用于炮兵等无法仅由 tag 区分的场景；少量数据异常才进入例外表。

| 生态位 | 主判定 |
|---|---|
| 火枪 | `AbstractMusketeer` |
| 散 | 先取 `AbstractSkirmisher` 或 `AbstractFootArcher`，再确认远程攻击有反重步倍率，或官方 tooltip 明确说明擅长对付步兵/重步。阿兹特克弓箭武士虽带散兵标签，但主职反炮，不填散位。 |
| 冲击位（“马”） | `AbstractHandCavalry`，或同时具有 `AbstractHandInfantry` + `AbstractLightInfantry` 的近战轻步。后者包括弯刀勇士和郊狼游击兵：它们与重骑一样会被火枪反制，承担切散、切炮、压后排的同一战术位置。 |
| 龙骑 | `AbstractRangedCavalry` 或 `AbstractRangedShockInfantry`。例如阿兹特克鹰游击武士以第二种方式进入龙骑位。 |
| 近战反骑重步 | 同时具有 `AbstractHandInfantry` + `AbstractHeavyInfantry`，且近战攻击对 `AbstractCavalry` 有倍率。`AbstractPikeman` 不单列：长枪兵、美洲狮矛兵、剑盾手、长刀武士、拉杰普特人和战棍兵都由这一规则自然覆盖。 |
| 反步兵炮 | `AbstractArtillery`，且远程攻击具对步兵倍率，或官方 tooltip 明确说明擅长对付步兵；纯反炮的 culverin 和攻城迫击炮不填此位。 |

一个单位可同时填多个生态位。豹游荡武士既有近战反骑能力，也以反重步为主；步枪骑兵既是龙骑，又有反重步、反炮能力。主生态位决定它可填哪些通用骨架，次生态位参与双方对位画像和国家战术的候选生成，不把同一单位拆成多个槽位。

只有以下情况才使用小型例外表：逻辑标签不能表达真实克制关系、数据缺失或异常、或群测证明某条通用判定产生不合理候选。例外表只能增删某一单位的某一生态位或调整权重，不能复制整套单位职业档案。

4. 每个骨架是“需求生态位”而不是写死单位名。国家只在当前时代能凑齐对应生态位时才获得该候选；例如加塞尼亚步兵 + 弯刀勇士可生成火枪马，日本可自然生成足轻 + 薙刀骑兵、足轻 + 火焰之箭，西班牙可生成重步散或长矛骑兵 + 散兵，法国可生成胸甲骑兵 + 散兵。
5. 专属兵是高权重核心候选，不是强制槽位。它只有能填入一个可用骨架或该国明确的特殊体系时才入选。
6. 第三兵种不能随机追加。它必须是某个骨架定义的扩展槽，例如散龙炮或日本的足轻 + 长弓 + 薙刀骑兵；否则国战优先使用可读性更好的两兵种组合。
7. 每个骨架先解析成“具体单位 id + 资源配比”的完整候选，再进入随机选择；不在开局时从匹配单位中随机抽槽位。两兵种和三兵种候选都必须定义各槽位资源占比，不能复用普通斗蛐蛐的均分数量器。
8. 无法映射到常见组合、或多生态位核心确实改变打法的文明，才使用显式的国家特殊体系。特殊体系写入 `civ_war_archetypes.json`，不在代码中点名散落规则。
9. 运行时双方独立选兵，不根据对手追求五五开：先按 75%/25% 选择纯本国或混编来源，再在该来源可实现的战术中等概率选一种，最后才在该战术内部选择具体兵种和比例版本。具体组合数量多的战术不会因此获得更高概率。
10. 不惩罚战术镜像，也不排除正常天克。法国龙骑散对荷兰龙骑散、重步散克制散马等都属于玩法本身。
11. 静态画像和真实模拟器只用于离线发现单方坏阵容、校准资源比例和定位数据异常，不参与正式开局选择，不预跑或缓存最终战斗。

### 第一轮资源配比基线

以下比例已经进入 `civ_war_archetypes.json`，用于生成可重复审计的数量，也是当前正式运行口径。数量器保证每槽至少一个单位，再以最小化实际资源占比误差的方式填满预算。

比例校准当前冻结，不继续做离线模拟或调整；以上第一轮比例就是当前正式运行口径。只有玩法方明确重新开启时，才讨论是否需要校准及采用什么方法。

| 编制 | 按槽位顺序的资源占比 |
|---|---|
| 火枪马 | 火枪 60% / 冲击 40% |
| 龙骑散 | 龙骑 45% / 散 55% |
| 散马 | 散 60% / 冲击 40% |
| 火枪炮 | 火枪 70% / 炮 30% |
| 龙骑炮 | 龙骑 65% / 炮 35% |
| 火枪散 | 火枪 50% / 散 50% |
| 重步散 | 近战反骑重步 40% / 散 60% |
| 散龙炮 | 散 45% / 龙骑 30% / 炮 25% |

运行时静态画像只负责把候选空间压缩为短名单。离线审计工具仍可用于定位单方坏阵容、无贡献单位或数据异常，但不用于调整当前冻结的资源比例，也不作为某一场押注战的预演或缓存结果。

### 常见骨架覆盖核验（3 时代）

此前按原始 type 标签得到的“21 个文明至少有 3 套”只是初筛，不能再作为设计结论：加塞尼亚步兵 + 弯刀勇士、鹰神弓箭手 + 斧头骑兵等事实证明，单位的玩家生态位不能由是否带 `AbstractHandCavalry` 等标签决定。

下一轮审计以本节生态位映射重新枚举 24 个文明、各时代和各预算。结论仍应是：常见骨架作为主路径，国家战术只服务于真实缺口或确有独特打法的多生态位核心，不能因为文明有特色兵就机械地另写一套例外代码。

领事馆兵可参与候选，但候选排序先看不依赖领事馆的本国核心；领事馆用于补齐已有体系的槽位或扩展体系，而不是把中国、日本、印度的主力随机替换成另一文明的常规军。这样保留其合法军力身份，也维持国战的国家辨识度。

候选不按具体组合数量平抽，选择顺序固定为：

1. 有国家优势策略时，先按 `50% 优势策略 / 50% 普通策略` 选择顶层类型；没有优势策略时全部进入普通策略。
2. 抽中优势策略后，直接在该文明已定义的完整优势策略中等概率选择，兵种和固定/资源比例随策略确定，不再经过领事馆来源抽取。
   优势策略允许 1 至 3 个兵种：单一标志性强兵可以独立成军，不强行为“生态位完整”补入其他单位。
3. 抽中普通策略后，按 `75% 纯本国 / 25% 混编` 选择来源；25% 池统一包含佣兵、亡命徒和领事馆兵，不另设三类权重。某类不存在时自动使用另一类。纯外援编制禁止进入候选，例如“中国军队 = 英国红衣军 + 葡萄牙弩手”不允许出现。
4. 在当前来源可实现的通用战术中等概率选一种，最后才在该战术内部选择具体兵种和比例版本。具体组合数量多的战术不会因此获得更高概率。

### 离线：模拟器审计与精确覆盖

开发和数据刷新时，用批量脚本枚举文明、时代、预算和候选编制，调用真实模拟器检查：

- 一边持续碾压的比例；
- 某兵种长期零击杀、低伤害或只充当无效肉盾的比例；
- 角色覆盖不足和高频镜像组合；
- 同一文明是否只会生成一套阵容。

审计发现的问题不通过全局战力阈值修补，而是进入 `civ_war_overrides.json`：按文明精确排除无效组合，或为缺乏常规角色的文明补充可行模板。数据刷新时必须校验这些 id 和组合是否仍存在。

不采用“攻击低于 X 自动禁用”一类全局阈值。若数据刷新或群测证明某个精确组合无节目效果，记录到可审计的国战编制覆盖表中处理。

## 三文明试跑（历史材料）

仅用于记录当时的验证方向，不作为胜负结论、平衡依据或待办：

## AOE 参数与科技解锁（研究记录，未改实现）

### 已确认

- `damagearea` / `damagecap` 是攻击动作级字段，二者可独立存在：
  - 全量 `protoy.xml` 中，有 cap 无 area 102 个动作；
  - 有 area 无 cap 55 个动作；
  - 二者同时存在 596 个动作。
- 因此不能把 `damagecap` 继续解释为“仅 AOE 才有的溅射总伤害池”。它至少是攻击动作级伤害上限，AOE 只是同时读取 `damagearea` 和成长科技。
- 已确认“无 area 但有 cap”既包含运行时补 AOE，也包含通用 cap。利菲迪骑士 `deLifidi`、突袭者 `deRaider` 的 cap-only 近战动作，确认由豪萨主城科技 `DEHCDurbarParade` 解锁 AOE：
  - `MeleeHandAttack` +1.00 DamageArea
  - `TrampleHandAttack` +2.00 DamageArea
  - 影子科技 `DEHCDurbarParadeShadow` 继续为 `DefendHandAttack`、`GuardianAttack` +1.00 DamageArea
- `.tactics` 已确认存在 `outerdamageareadistance`、`outerdamageareafactor`、`areasortmode`。这说明 AOE 有内外圈衰减和目标排序，不是圆内等额伤害或随机抽人。
- `basedamagecap` 出现在带 cap 的动作上，用于 cap 随 BasePercent 科技缩放；不是“2×基础伤害”的替代字段。
- 2022 年官方论坛讨论与场景编辑器实测支持以下口径：
  - 主目标吃完整基础伤害；`damagecap` 不限制主目标。
  - `damagecap` 限制主目标之外的 AOE 伤害总量或分配预算，不等同于“每个副目标各自的上限”。
  - 倍率先参与计算，cap 随伤害与倍率增长；例如铁连枷基础 20、cap 40，仍可对散兵造成最高 60 的伤害。
  - 单个副目标实际伤害受距离和落点影响，近处高、远处低，所以不能简单写成 `cap / 实际溅射人数`。
- 实机样本：
  - 榴弹兵基础 16、cap 36、AOE 3，打 3×3 火枪阵时稳定伤到 3 人：主目标 16，另外两人约 11-14，总伤约 40。
  - 将榴弹兵 cap 翻倍到 72 后，测试得到总伤约翻倍且命中人数增加到 6。
  - 旧版风琴炮 30×6、cap 60，紧密阵型测试单次总伤约 671；帝国胸甲单次多目标总伤约 129-155。说明实际总伤可超过静态 cap，也说明当前 `cap / 人数` 模型过于确定。
- 近战与炮击的命中形状不同：旧版实测中骑兵近战呈方向性线/锥形，炮击更接近命中点前方的半圆/圆形；`areasortmode` 和 `.tactics` 参数与此对应。
- 伤害成长与 cap：
  - 官方科技树中 `DamageCap` effect 只有 2 条，均属日本和尚特殊升级；普通伤害升级只写 `Damage`。
  - `basedamagecap` 仅 13 条动作使用，其中 10 条同时有 cap、3 条只有 basedcap；它不是绝大多数 cap 的缩放开关。
  - 因此常规规则应理解为 cap 与伤害成长联动，而不是每项科技都单独更新 cap。
- 斗蛐蛐当前实现已做对的部分：
  - `apply_upgrades()` 会在时代伤害倍率变化时同步缩放已有 `damage_cap_ranged/melee`。
  - `_apply_one_tech()` 会在普通 `Damage` 科技变化时同步缩放已有 cap。
- 斗蛐蛐当前实现仍有风险：
  - 模拟器先计算 `min(damage_cap / splash_count, base_atk)`，再乘克制倍率与护甲。
  - 公开实机证据支持“倍率先计入，cap 随倍率一起增长”，例如铁连枷基础 20、cap 40，对散兵仍可造成最高 60 伤害。当前顺序会把 cap 切成未乘倍率的预算，可能低估对克制目标的溅射。
  - `DamageBonus` 型克制科技当前只改 `multipliers_*`，不会同步改变 cap；需要与引擎的“cap 随倍率增长”规则一起核实。

### 暂不改动

- 不据此修改模拟器 AOE 公式。
- 不把 `damagecap / 人数` 认定为原版规则。
- 不把当前“最多 round(radius) 人、随机抽取”当作 AoE3 实际规则。
- 不批量把科技 `DamageArea` 效果写进 `seeds/aoe3/units.json`，先保留为研究证据。

### 后续待核

- 仍需拿到引擎级实现或一致的重现实测，精确确认 cap 与距离衰减、命中顺序、护甲、倍率、多发弹丸的完整计算顺序。
- 当前证据更支持“主目标另算 + 副目标总预算/分配上限”，但尚不能写出精确公式。
- 核实伤害升级、`DamageBonus`/隐藏倍率、护甲与 cap 的结算先后；当前最可疑点是 cap 在倍率前分摊。
- 建立 `DamageArea` 科技效果的完整映射，区分国战当前时代是否实际可研究。
- 核对外圈伤害公式，尤其是 `outerdamageareadistance` 到 `outerdamageareafactor` 之间的插值方式。
- 仅在数据证据、玩法目标都明确后，再决定是否扩展模型或 UI。
