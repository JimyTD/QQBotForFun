# 帝国3斗蛐蛐国战 WIP

> 状态：设计中，尚未编码。

## 已确定

- 入口：`斗蛐蛐 国战` 随机两个主文明；`斗蛐蛐 国战 文明A 文明B [预算] [N时代]` 指定对阵。
- 只使用 `civs.json` 中 24 个可玩主文明；不纳入革命、战役文明、原住民部落或盟友单位。
- 时代规则沿用普通斗蛐蛐：兵池按时代限制，逐时代单位改良和土著/亡命徒/佣兵类别科技继续生效。
- 普通对局和国战都不使用随机通用科技。未来科技只能来自本国、可解释且公开展示的科技树或主城国策。
- 国战重点是“国家战术编制”，不是把文明可用单位简单随机拼在一起。

## 国家正规军池

候选单位先通过普通斗蛐蛐的安全过滤，再额外排除英雄、探险家和宠物。村民（包括法国库尔人）、纯治疗者、建筑、船、占位符、战役垃圾单位、彩蛋和怪物都不入国战。

雇佣兵和亡命徒是游戏内合法军力，不全局禁止；但国家常规军和特色兵优先级更高，不能让雇佣兵把国家辨识度挤掉。

## 战术编制生成

### 运行时：生成而非预演

1. 按 type 标签把单位标记为前排、远程输出、冲击/机动、反骑、反重步、炮兵等战术角色；一个单位可兼任多个角色。
2. 每个文明先生成 2 至 3 兵种的候选编制，不做一次随机抽兵就直接开战。
3. 候选以“核心 + 补位”模板生成：
   - 前排 + 远程输出；
   - 前排 + 机动/冲击；
   - 远程输出 + 机动/冲击；
   - 炮兵 + 保护兵种；
   - 某文明确实缺少上述角色时，允许其走本国可行的特殊体系。
4. 专属兵是高权重核心候选，不是强制槽位。它只有能与本国其他兵组成有效编制时才入选。
5. 同角色弱兵堆叠会被候选生成器拒绝，前提是该文明存在能补足短板的替代兵种。例如西班牙的长枪兵 + 剑盾手不会作为默认编制；若是长枪兵 + 龙骑兵、剑盾手 + 弩手等能形成互补，则保留为候选。
6. 每个候选计算资源归一化的战斗画像：耐久、持续伤害、射程、速度、AOE 和可覆盖的克制目标。画像只用于候选排序和双方接近度比较，不作为“某兵低于 X 就禁用”的全局阈值。
7. 最终从总画像接近、角色互有应对、但打法不完全镜像的若干候选对阵中随机选一组。最终实战不在开局前预跑，押注前没有结果缓存。

### 离线：模拟器审计与精确覆盖

开发和数据刷新时，用批量脚本枚举文明、时代、预算和候选编制，调用真实模拟器检查：

- 一边持续碾压的比例；
- 某兵种长期零击杀、低伤害或只充当无效肉盾的比例；
- 角色覆盖不足和高频镜像组合；
- 同一文明是否只会生成一套阵容。

审计发现的问题不通过全局战力阈值修补，而是进入 `civ_war_overrides.json`：按文明精确排除无效组合，或为缺乏常规角色的文明补充可行模板。数据刷新时必须校验这些 id 和组合是否仍存在。

不采用“攻击低于 X 自动禁用”一类全局阈值。若数据刷新或群测证明某个精确组合无节目效果，记录到可审计的国战编制覆盖表中处理。
