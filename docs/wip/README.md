# WIP 文档

- **Status**: Accepted
- **Last Updated**: 2026-10-08
- **Owner**: @JimyTD

`docs/wip/` 是本项目唯一存放**活跃**未完成方案的目录。这里的规则、设计和实现边界都在变化，不能当作正式功能说明。

`docs/wip/` 只接收正在设计或实现、预计最终会并入正式功能文档或被明确废弃的方案。Shelved、Archive、Research 等不再活跃推进、仅供查阅的资料继续放在各自的参考区域，不进入 WIP 索引，也不按 WIP 的完成删除流程处理。

## 存放规则

- 正在推进、仍在变更的方案统一放 `docs/wip/<topic>.md`。
- 目录名 `wip` 已经表明状态，文件名不再重复添加 `-wip`。
- WIP 文档顶部必须写明状态、最后更新时间和对应正式文档；没有正式文档时写明预期落点。
- 一个主题只保留一份 WIP 文档。方案被替换时直接更新原文件，不并排堆积版本。
- 正式功能文档和代码才是运行口径；WIP 与正式文档冲突时，以正式文档和代码为准。

## 完成与并入

只有 Owner 或用户明确确认仍有效的内容已经实现并稳定、方案已废弃，或已被正式功能文档取代后，才能启动收口。代码已经实现不等于可以自动关闭 WIP。

收口时只把已经生效的真实功能并入对应正式文档：

- 当前生效的规则、入口、边界、失败处理和必要的背景。
- 已经影响正式功能的数据来源、配置或兼容性要求。
- 当前有效的性能预算或约束；历史测量、基准对比和调参过程仍留在 Git 历史。

以下内容不得并入正式文档：

- 开发过程、排查时间线、历史性能测量和一次性验收记录。
- 被推翻的假设、错误探索、废弃方案和被淘汰参数。
- 已由代码或正式文档覆盖的“已完成”清单。
- 只为解释某次改动而存在的临时文件列表、日志摘录和调参过程。

正式功能文档只描述已经实现的实际行为，不写已批准但尚未实现的设计。尚未实现或仍在推进的内容继续保留在 WIP 中。

部分完成时默认原地更新原 WIP：删除已经被正式文档和代码覆盖的部分，保留剩余范围。只有剩余工作形成独立目标、独立负责人或需要另一个正式文档落点时，才拆成新的 WIP。

当 WIP 中已经没有仍有效的未完成内容时，直接删除原文件；不改名为历史或归档文档，也不在 `docs/plans/`、`docs/games/` 等处保留副本。需要追溯过程时使用 Git 历史。
